노트북 사전 점검

실습은 노트북 터미널에서 SSH로 서버에 접속해서 진행합니다. 클라우드마다 콘솔 화면은 다르지만, 리눅스 서버에 SSH로 접속하는 방식은 AWS, Azure, GCP, 국내 클라우드 모두 같습니다. 강의 전에 아래 두 가지를 확인해 주세요.

1SSH 프로그램 설치 여부

PowerShell에서 실행합니다.

ssh -V

OpenSSH_for_Windows_...처럼 버전이 나오면 준비 완료입니다. "인식되지 않습니다"가 나오면 설정 → 앱 → 선택적 기능 → OpenSSH 클라이언트를 추가합니다.

회사 노트북이라면

보안 정책으로 OpenSSH가 빠져 있거나 설치가 막혀 있을 수 있습니다. 설치가 안 되면 강의 당일에는 개인 노트북을 준비해 주세요.

터미널에서 실행합니다.

ssh -V

Mac에는 기본으로 설치돼 있어서 OpenSSH_9...처럼 버전이 나옵니다.

2외부 22번 포트 연결 가능 여부

실습 서버가 없어도 확인할 수 있습니다. 강의 당일에는 강의장 Wi-Fi에 연결한 상태로 한 번 더 확인합니다.

Test-NetConnection github.com -Port 22

TcpTestSucceeded : True가 나오면 정상입니다.

nc -zv github.com 22

succeeded가 나오면 정상입니다.

22번 포트가 막혀 있다면
  • 휴대폰 테더링으로 연결을 바꾼 뒤 다시 확인합니다. 모바일 데이터는 22번 포트를 대부분 막지 않습니다.
  • SSH는 텍스트만 주고받아 데이터 사용량이 적습니다. npm install, Kiro 설치처럼 용량이 큰 내려받기는 AWS 서버에서 일어나므로 휴대폰 데이터와 관계없습니다.
  • 테더링도 어렵다면 Step 1 아래의 브라우저로 접속하기를 씁니다.

실습 전 확인 사항

  • 비밀번호, .env 내용, .pem 키 파일은 캡처하거나 메신저로 보내지 않습니다.
  • AWS 콘솔에서 "업그레이드", "고급 기능 활성화"는 누르지 않습니다. 유료 플랜으로 바뀌어 요금이 나갈 수 있습니다.
  • 1일차가 끝나도 인스턴스를 중지하거나 종료하지 않습니다. 2일차에 같은 서버를 이어서 씁니다. 종료는 2일차 마지막 Step 19에서 함께 합니다.
  • 여기서 쓰는 서버는 실습용입니다. 2일차에 일부러 고장 내는 실습은 실제 운영 서버에서는 하지 않습니다.

Step 0

AWS에 내 서버(인스턴스) 만들기

0-1리전 확인과 EC2 이동

  1. AWS 콘솔에 로그인합니다.
  2. 리전은 계정에 할당된 그대로 씁니다. 새 무료 플랜 계정은 리전 하나로 정해져 있고(예: 시드니), 다른 리전은 유료 플랜이 필요합니다. 서울이 아니어도 실습에는 문제없습니다.
  3. 맨 위 검색창에 EC2를 입력하고 EC2를 누릅니다. 리전 이름은 EC2 화면 오른쪽 위에 보입니다.
  4. 주황색 인스턴스 시작 버튼을 누릅니다.

0-2이름과 운영체제

  • 이름 및 태그: quotation-lab-본인이름
  • 애플리케이션 및 OS 이미지: Ubuntu를 누르고, Ubuntu Server 26.04 LTS가 선택됐는지 확인 (프리 티어 사용 가능 표시)

0-3인스턴스 유형

t3.micro (2 vCPU, 1GiB 메모리, 프리 티어 사용 가능)가 기본으로 골라져 있으면 그대로 둡니다.

0-4키 페어 만들기

  1. 키 페어(로그인) 오른쪽의 새 키 페어 생성을 누릅니다.
  2. 이름 quotation-key, 유형 RSA, 형식 .pem → 키 페어 생성
  3. 다운로드 폴더에 quotation-key.pem이 생겼는지 확인합니다. 이 파일이 없으면 서버에 접속할 수 없고, 다시 내려받을 수도 없습니다.

0-5네트워크 설정 (보안그룹)

  • 보안 그룹 생성이 선택돼 있는지 확인
  • 다음에서 SSH 트래픽 허용: 이미 체크돼 있음, 옆은 위치 무관 그대로
  • 인터넷에서 HTTPS 트래픽 허용: 체크하지 않음
  • 인터넷에서 HTTP 트래픽 허용: 직접 체크

아래에 0.0.0.0/0 관련 노란 경고가 나와도 실습에서는 그대로 진행합니다. 이렇게 하면 22번(SSH)과 80번(HTTP) 포트만 열립니다. DB가 쓰는 5432번은 열지 않습니다.

0-6스토리지 확인과 인스턴스 시작

  1. 스토리지 구성은 기본값(8GiB, gp3) 그대로
  2. 오른쪽 요약에서 이름, OS, 유형, 키 페어, 보안그룹, 스토리지 여섯 가지 확인
  3. 인스턴스 시작 → 성공 화면에서 모든 인스턴스 보기

0-7퍼블릭 IP 확인

  1. 인스턴스 상태가 실행 중이 될 때까지 기다립니다 (보통 1분 안, 새로고침 버튼 사용).
  2. 내 인스턴스 줄을 누르면 아래에 세부 정보가 나옵니다. 퍼블릭 IPv4 주소를 복사합니다.
  3. 이 가이드 오른쪽 위 "내 퍼블릭 IP" 칸에 붙여 넣으세요. 이제부터 명령의 퍼블릭IP가 내 주소로 바뀝니다.
Step 1

노트북에서 서버에 접속하기

Windows: 시작 메뉴에서 PowerShell을 열고 아래를 한 줄씩 실행합니다.

cd $HOME\Downloads
ssh -i .\quotation-key.pem ubuntu@퍼블릭IP

Mac: Cmd+Space → "터미널"을 열고 아래를 한 줄씩 실행합니다.

cd ~/Downloads
chmod 400 quotation-key.pem
ssh -i quotation-key.pem ubuntu@퍼블릭IP

처음 접속하면 아래 질문이 나옵니다. yes를 끝까지 입력하고 엔터 (y만 치면 안 됩니다).

화면
Are you sure you want to continue connecting (yes/no/[fingerprint])?
정상이면

Welcome to Ubuntu 26.04 ...가 나오고 마지막 줄이 ubuntu@ip-172-...:~$로 바뀝니다. 이제부터 이 창에 입력하는 명령은 서버에서 실행됩니다. 여기서부터는 Windows와 Mac의 명령이 같습니다.

안 되면

화면에 보이는 것할 일
Connection timed out퍼블릭 IP 오타, 보안그룹 22번, 인스턴스가 실행 중인지 확인. 모두 맞다면 강의장 Wi-Fi가 22번 포트를 막고 있을 수 있으니 사전 점검 2로 확인하고 휴대폰 테더링으로 바꿔 다시 접속
Permission denied (publickey)사용자 이름이 ubuntu인지, 키 파일 이름이 맞는지 확인
UNPROTECTED PRIVATE KEY FILE / bad permissionsMac: chmod 400 quotation-key.pem 다시 실행Windows: 아래 두 줄 실행 후 다시 접속
icacls .\quotation-key.pem /inheritance:r
icacls .\quotation-key.pem /grant:r "$($env:USERNAME):(R)"

ssh를 인식하지 못한다고 나오면: 설정 → 앱 → 선택적 기능 → OpenSSH 클라이언트 추가

노트북 SSH를 쓸 수 없을 때: 브라우저로 접속하기

OpenSSH를 설치할 수 없거나 테더링으로도 22번 포트가 막힐 때 쓰는 대안입니다. AWS 콘솔이 서버에 대신 접속해 주므로 키 파일이 필요 없고, 강의장 네트워크의 22번 차단과도 상관없습니다.

  1. AWS 콘솔 → EC2 → 인스턴스에서 내 인스턴스를 체크하고 위쪽 연결을 누릅니다.
  2. EC2 Instance Connect 탭에서 사용자 이름이 ubuntu인지 확인하고 연결을 누릅니다.
  3. 브라우저 새 탭에 서버 터미널이 열립니다. 이후 명령은 Step 2부터 같습니다. 창이 두 개 필요한 단계에서는 같은 방법으로 탭을 하나 더 엽니다.

브라우저 터미널은 붙여 넣기 단축키가 브라우저와 겹치거나 오래 두면 접속이 끊길 수 있습니다. 가능하면 노트북 SSH를 먼저 쓰세요.

실습 중 접속이 끊기면

서버에 설치한 것은 그대로 있습니다. 같은 명령으로 다시 접속해서 하던 단계부터 이어 가면 됩니다. command not found가 나오면 먼저 프롬프트가 ubuntu@ip-...인지(서버 안인지) 확인하세요.

Step 4

PostgreSQL 설치와 앱 전용 계정, DB 만들기

4-1설치와 상태 확인

sudo apt install -y postgresql postgresql-contrib
sudo systemctl status postgresql

초록색 active가 보이면 정상입니다. active (exited)로 나와도 정상입니다. 화면에서 빠져나올 때는 q를 누릅니다.

4-2DB 관리 화면으로 들어가기

sudo -u postgres psql

프롬프트가 postgres=#로 바뀝니다. 여기는 SQL을 입력하는 화면입니다.

4-3앱 전용 계정과 DB 만들기

한 줄씩 붙여 넣고 엔터. 원하는_비밀번호는 직접 정한 비밀번호로 바꾸고, 작은따옴표는 그대로 둡니다. 비밀번호는 메모해 두세요. Step 5, 6에서 다시 씁니다.

CREATE USER quotation_app WITH PASSWORD '원하는_비밀번호';

CREATE ROLE이 나오면 다음 줄로.

CREATE DATABASE quotation_lab OWNER quotation_app;

CREATE DATABASE가 나오면 성공입니다. 줄 끝 ;를 빼먹으면 아무 반응 없이 프롬프트가 postgres-#로 바뀝니다. 그럴 땐 ;만 입력하고 엔터.

4-4확인 후 나가기

\l quotation_lab

Owner 칸에 quotation_app이 보이면 됩니다. 화면 맨 아래에 (END)가 보이면 q를 눌러 닫습니다.

\q

\q를 입력하고 엔터를 쳐야 ubuntu@ip-...:~$로 돌아옵니다.

Step 5

앱 코드 받기와 표 만들기

5-1코드 내려받기

cd ~

마지막 줄에 'quotation-lab.zip' saved가 나오면 됩니다.

5-2unzip 설치와 압축 풀기

Ubuntu 26.04에는 unzip이 기본으로 없어서 먼저 설치합니다.

sudo apt install -y unzip
unzip quotation-lab.zip
cd quotation-lab
ls -a
정상이면

package.json, .env.example, db 같은 이름이 보입니다.

5-3앱 계정으로 표 만들기

psql -h localhost -U quotation_app -d quotation_lab -f db/schema.sql

Password for user quotation_app:가 나오면 4-3에서 정한 비밀번호를 입력합니다. 입력해도 화면에 아무것도 안 보이는 게 정상입니다. 그대로 치고 엔터.

정상이면

CREATE TABLE이 나오고 ERROR가 없습니다.

psql -h localhost -U quotation_app -d quotation_lab -c "\dt"

quotations, quotation_items 두 표가 보이고 Owner가 quotation_app이면 됩니다.

Kiro가 cat .env처럼 비밀번호가 그대로 보이는 명령을 제안하면, 실행해서 결과를 붙여 넣는 순간 비밀번호가 AI에게 넘어갑니다. 대신 값을 가리고 다른 줄만 확인합니다.

diff ~/quotation-lab/.env ~/quotation-lab/.env.backup | sed 's/=.*/=****/'

Kiro에게는 "cat은 비밀번호가 노출돼서, 값을 가린 diff 결과를 보여 줄게"라고 말하고 결과를 붙여 넣습니다.

Kiro의 해결 제안도 검증하기

설명과 실제 명령이 맞는지, 더 작게 바꾸는 방법은 없는지 따져 봅니다. 예: "비밀번호가 맞는지 시험한다"면서 사용자 목록만 보는 명령, 멀쩡한 DB 비밀번호 자체를 바꾸는 ALTER USER. 이번 원인은 .env 한 줄이라, 가장 작은 조치는 백업으로 되돌리는 것입니다 (7교시).
